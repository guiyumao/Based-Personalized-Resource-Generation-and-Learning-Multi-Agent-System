- 需求：学生生成学习路径时，公共知识库缺失不再只生成“个人草稿等管理员补建”，而是直接补充进知识库，下次直接检索命中、无需重生成。

  - `services/agent_service/app/services/learning_path.py`：personal_draft 分支生成草稿后调用入库，成功后重新 `require_plan_knowledge` 并把本次请求升级为 public 模式（payload 带 subject_id / knowledge_versions）。
  - `plan_knowledge.py` 提示文案、前端 `LearningPathView.vue` / `ResourceView.vue` 文案同步更新。
- 测试：`tests/unit/test_knowledge_bootstrap.py` 两个用例改为断言入库后即 public 且二次预检 ready；新增 `test_promote_draft_rolls_back_when_publication_fails`；`tests/unit/test_plan_knowledge_p1.py` 用例改为断言自动补建 + gap RESOLVED，并清理 auto_* 残留行（夹具清理不到会导致后续用例 FK 报错），同时把 `plan_knowledge.KNOWLEDGE_ROOT` 指回运行时根以保证端到端一致。

## 第二轮：可靠性收尾（事务一致性 / 并发去重 / 质量标注）

- 事务一致性：`promote_draft_to_knowledge_base` 全程持有 `knowledge_write_lock`（带 8s 有界等待与所有权继承），失败走 `_compensate_publication()`：按「DB 行 → 语料文件(md→.pending) → Chroma(where 删除 subject+source) → reconcile()」顺序补偿，幂等可重复；补偿不完整时写 AuditLog ERROR 并排队 `RECONCILE_PUBLICATIONS` 恢复任务，绝不伪装成功。返回契约改为 `{"ok":True/False,"reason":...}`。
- 并发去重：写入前用规范化名匹配（`normalize_name`）复用已有活跃版本；候选按 (subject code, point) 复用，禁止重复候选；管理员 WITHDRAWN/REJECTED 的知识不再自动补建；`auto_<hash>` 学科码基于规范化名。
- 质量标注：新增 `AUTO_APPROVED` 状态（区别于人工 APPROVED），`reviewed_by/at` 保持空，`_document()` 写入「来源类型: ai_generated_auto_published / 审核状态: 未经人工审核」；`PUBLISHABLE_STATUSES`、`edit_candidate`、任务队列、知识复用过滤均已放行/区分该状态；管理端 `review.vue` 显示「AI 自动生成（未人工审核）」。
- 发布后校验 `_verify_publication()`：文件存在 + sha256(document_version) + Chroma 命中同 subject/source/版本 + 正文含知识点名。
- 场景 B 修复：语料只发布“当前缺失的知识点”，不再整科重写。

## 第三轮：P0 归因 / P1 真实运行时 / P2 前端测试 / P3 运维化 / P4 提交分离

- **P0 归因（已闭环，20 个失败全部消除）**
  - 14 个（test_vulnerability_policy 11 + test_teaching_migration_repair 2 + test_knowledge_lock 1）：**根因是 `LSBOX_SHMEM_NAME`**。
    `scripts/run_no_cost_tests.py::isolated_environment()` 用白名单裁剪环境，把宿主沙箱必需的 `LSBOX_SHMEM_NAME` 删掉；之后任何 Python 子进程都被沙箱静默杀死（RC=1、stdout/stderr 全空、连 `python -c "print(1)"` 都不执行）。
    二分证据：父进程环境替换为 isolated 集合后子进程必失败；把 `LSBOX_SHMEM_NAME` 加回去立刻恢复（其它 LSBOX/SANDBOX 变量无效）。与守卫（guard.py）、sitecustomize、pytest 顺序均无关。
    修法：给 `isolated_environment()` 增加 `NO_COST_PASSTHROUGH_ENV`（逗号分隔的显式透传名单，默认不传任何东西，白名单仍是默认规则），未硬编码 WorkBuddy 专有变量。运行时 `NO_COST_PASSTHROUGH_ENV=LSBOX_SHMEM_NAME,... pytest` 即可。
