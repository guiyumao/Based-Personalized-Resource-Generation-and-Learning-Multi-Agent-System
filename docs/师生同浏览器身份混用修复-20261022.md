# 师生同浏览器身份混用修复

日期：2026-10-22。

## 根因与复现

学生页显示 student 却收到 `Requires one of roles: student`，教师页显示 teacher111 却收到 `Requires one of roles: teacher, admin`。实际数据库中 student=学生、teacher111=教师，分别携带自己的凭证读取接口均正常，不应修改账号角色或放宽后端权限。

原页面身份来自各标签页内的 Pinia，但 Axios 每次请求和助手流式请求都重新读取跨标签页共享的 localStorage。另一标签页登录不同角色后，旧页面显示原身份，却携带了另一个账号的凭证。main.ts 启动时虽然调用 users/me，却未用返回身份更新缓存显示。

此前端到端验收采用独立 browser context，未覆盖共享 localStorage 的同浏览器多标签页。此次在修复前新增同 context 多标签页复现，真实教师页的班级查询及创建返回403，记录位于 `artifacts/auth-tab-baseline/api.log`、`failure.json`、截图。保留后端角色拒绝，没有以关闭权限通过测试。

## 修复

- `web-app/src/stores/auth.ts`：新增 sessionStorage 的 `learning-system-tab-auth`，各标签页保留自己的登录；localStorage 仅为尚无标签页会话的新页面提供默认登录。退出只清除本标签页，对不同账号的共享默认会话不做删除；明确退出的标签页刷新后不会自动切换为另一账号。
- `web-app/src/api/http.ts`、`api/assistant.ts`：普通与流式请求统一使用当前 Pinia token，和页面身份保持一致。旧登录请求延迟返回401时，不清掉后来切换的新登录。
- `web-app/src/main.ts`、`router.ts`：使用服务器 users/me 的真实身份校正缓存，核对响应属于同一 token；身份校正不会覆盖另一个标签页的默认登录。
- `TeacherClassPanel.vue`：刷新成员同步刷新班级人数；切换班级后丢弃旧班级迟到的成员响应。
- `TeacherView.vue`：同名班级卡片增加编号，失败时不再以“暂无学生洞察”冒充成功空数据，角色错误提供中文提示。
- 保留同期浅色主题设置，只修正默认常量未使用导致的 TypeScript 构建失败，不改变默认配色。

无后端、数据库、成员关系、分数或权限策略修改，无迁移或服务重启，无付费模型调用。

旧页面如已保留混用的登录缓存，请在教师和学生标签页各自重新登录一次。之后可以在同一浏览器同时保留两种身份，刷新不会互相换号。新开标签页仍使用最后一次登录作为默认；若要换角色，在该标签页退出后登录即可。
