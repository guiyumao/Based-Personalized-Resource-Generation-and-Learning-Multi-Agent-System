# 系统改进路线图

> 最近更新时间：`2026-07-17`

本文档把当前系统从“可运行”往“可持续优化”推进的方向拆开，目标是在**不大幅重构**的前提下，逐步把多智能体平台升级为可编排、可观测、可回滚、可评估的学习闭环系统。

## 1. 总体改进思路

改进顺序建议按下面四步推进：

1. 先固化契约，减少服务之间靠默认值和硬编码联动。
2. 再增强可靠性，先解决超时、降级、丢消息和状态丢失。
3. 再提升生成质量，把提示词、学科规则和评估标准外置。
4. 最后优化体验与维护性，让系统更容易扩展和复用。

核心原则：

- 以当前 Python + FastAPI + LangGraph 主链路为基线，不主动推倒重来。
- 优先改“数据流”和“接口契约”，其次改“生成策略”，最后改“UI 和周边体验”。
- 每次改动都能单独上线，不要求一次性完成全部重构。

---

## 2. 分维度改进建议

### 2.1 核心引擎

问题：

- 工作流固定，扩展新智能体时需要改协调器主流程。
- 冲突解决范围太窄，主要处理资源与评价的顺序问题。
- 同步执行依赖手动排序，智能体之间耦合偏高。
- 降级后状态只保留部分注释，完整上下文丢失。

可行方案：

1. **能力注册 + 拓扑排序**
   - 智能体显式声明 `inputs / outputs / writes / depends_on`。
   - 协调器按依赖图做拓扑排序。
   - 优点：扩展性最好，适合未来增加新智能体。
   - 缺点：需要整理现有智能体元数据。
   - 优先级：高
   - 工作量：8-12 人天

2. **保持 LangGraph，但引入插件注册表**
   - 继续用 StateGraph 作为执行底座。
   - 增加智能体注册中心和能力清单。
   - 优点：迁移成本低。
   - 缺点：调度灵活性不如完整 DAG。
   - 优先级：高
   - 工作量：5-8 人天

3. **事件驱动编排**
   - 所有智能体通过事件总线订阅/发布上下文。
   - 优点：解耦最好。
   - 缺点：迁移大，排查复杂。
   - 优先级：中
   - 工作量：15-25 人天

推荐：

- 先做方案 1 + 2 的组合，保留 LangGraph，但把能力描述、执行顺序和冲突规则标准化。

### 2.2 内容生成质量

问题：

- 生成计划依赖阈值和关键词。
- 审计只看长度和跑题，缺少结构与教学合理性检查。
- 变体独立调用 LLM，成本高。
- 学科特殊规则写死在代码里。

可行方案：

1. **配置驱动生成计划**
   - 把字数、题型配比、学科规则抽到 JSON/YAML。
   - 优点：改规则不改代码。
   - 缺点：需要配置治理。
   - 优先级：高
   - 工作量：4-6 人天

2. **多维度审计评分**
   - 增加清晰度、连贯性、示例质量、结构完整性四类评分。
   - 优点：比单纯长度检查更稳定。
   - 缺点：需要制定评分 rubric。
   - 优先级：高
   - 工作量：6-10 人天

3. **一次生成多变体**
   - 让模型一次返回多个风格版本，再按评分筛选。
   - 优点：减少调用次数。
   - 缺点：上下文过长时更依赖模型稳定性。
   - 优先级：中
   - 工作量：4-8 人天

推荐：

- 先把“生成计划”和“审计 rubric”配置化，再做多变体单次生成。

### 2.3 数据与知识管理

问题：

- RAG 知识库无版本控制。
- 知识点靠子串匹配，消歧弱。
- 画像依赖 LLM 解析，缺少置信度校验。
- 图谱与 SQL 异步同步，容易不一致。

可行方案：

1. **RAG 版本化**
   - 每次更新生成新版本集合，保留最近 N 个版本。
   - 优点：可回滚、可审计。
   - 缺点：存储占用增加。
   - 优先级：高
   - 工作量：6-10 人天

2. **知识点实体链接**
   - 建立知识点统一 ID，避免重复实体。
   - 优点：图谱、错题本、资源能统一引用。
   - 缺点：初始清洗成本较高。
   - 优先级：高
   - 工作量：8-12 人天

3. **画像置信度校验**
   - 用行为数据、答题记录和对话信息交叉验证画像结论。
   - 优点：减少画像误判。
   - 缺点：需要定义一致性规则。
   - 优先级：中
   - 工作量：5-8 人天

推荐：

- 先做版本化和统一 ID，再补画像校验。

### 2.4 学习路径与评价

问题：

- 路径模板固定。
- 掌握度更新过于线性。
- 报告完全依赖 LLM。
- 错题重练泛化，不够针对错误模式。

可行方案：

1. **多路径模板**
   - 按知识点类型自动选择“理论-实验-项目”“概念-例题-练习”等模板。
   - 优点：路径更贴教学场景。
   - 缺点：模板数量会变多。
   - 优先级：高
   - 工作量：5-8 人天

2. **SM-2 式掌握度更新**
   - 引入遗忘曲线和下次复习时间预测。
   - 优点：更符合记忆规律。
   - 缺点：需要历史复习数据。
   - 优先级：高
   - 工作量：6-10 人天

3. **模板 + LLM 润色报告**
   - 先结构化汇总，再让 LLM 润色。
   - 优点：省 token、减少漂移。
   - 缺点：模板需要维护。
   - 优先级：高
   - 工作量：4-6 人天

4. **按错误模式重练**
   - 将错题分成概念混淆、计算错误、审题错误、步骤缺失。
   - 优点：重练更精准。
   - 缺点：需要错误分类器。
   - 优先级：中
   - 工作量：6-8 人天

推荐：

- 先做路径模板和报告混合生成，再把错题重练细分。

### 2.5 多智能体协作

问题：

- 智能体之间上下文传递太长。
- 反馈输入容易堆积无关信息。
- 缺乏能力发现机制。

可行方案：

1. **标准上下文包**
   - 每个智能体只接收固定字段集。
   - 优点：减少耦合。
   - 缺点：需要统一 schema。
   - 优先级：高
   - 工作量：4-6 人天

2. **能力发现与声明**
   - 新智能体注册时声明输入、输出和副作用。
   - 优点：方便自动编排。
   - 缺点：需要注册中心。
   - 优先级：高
   - 工作量：5-8 人天

3. **上下文裁剪**
   - 为每类任务保留最相关摘要，不把完整历史全部塞进去。
   - 优点：节省 token。
   - 缺点：裁剪策略要调优。
   - 优先级：中
   - 工作量：3-5 人天

推荐：

- 先做标准上下文包，再做能力发现。

### 2.6 性能与可靠性

问题：

- LLM 降级链没有熔断。
- RabbitMQ 消息失败可能丢失。
- 同步调用 evaluation 影响协调器。
- 前端 6 个 Axios 实例重复配置。

可行方案：

1. **熔断器 + provider 跳过**
   - 失败率超过阈值后短时间跳过该 provider。
   - 优点：减少重复超时。
   - 缺点：需要状态缓存。
   - 优先级：高
   - 工作量：4-6 人天

2. **死信交换机 + 指数退避**
   - 消息失败后进入死信队列，按退避策略重试。
   - 优点：避免任务静默丢失。
   - 缺点：运维复杂度增加。
   - 优先级：高
   - 工作量：5-8 人天

3. **画像快照缓存**
   - 协调器直接读最近快照，避免同步远程查询。
   - 优点：降低链路延迟。
   - 缺点：需要接受短暂陈旧。
   - 优先级：高
   - 工作量：3-5 人天

4. **前端 API 客户端工厂**
   - 统一拦截器、重试、错误处理和服务发现。
   - 优点：减少重复代码。
   - 缺点：需要改一层封装。
   - 优先级：中
   - 工作量：2-4 人天

推荐：

- 先做熔断、重试、快照缓存，再整理前端客户端工厂。

### 2.7 用户体验

问题：

- 问答慢。
- 路径不能拖动。
- 错题本缺全局视图。
- 图谱加载慢。

可行方案：

1. **局部异步加载**
   - 问答和图谱分段加载。
   - 优点：首屏更快。
   - 缺点：页面状态更复杂。
   - 优先级：高
   - 工作量：4-7 人天

2. **全局视图 + 目录直达**
   - 错题本、资源页、路径页都保留总览入口。
   - 优点：减少迷路感。
   - 缺点：需要统一交互规范。
   - 优先级：高
   - 工作量：3-5 人天

3. **图谱懒加载**
   - 先展示中心节点，再按需扩展边和邻居。
   - 优点：更轻。
   - 缺点：交互逻辑更复杂。
   - 优先级：中
   - 工作量：4-6 人天

推荐：

- 优先做全局视图和局部异步加载。

### 2.8 安全与隐私

问题：

- JWT 降级路径不够安全。
- 画像数据缺少分级。
- 文件权限不够细。

可行方案：

1. **统一安全策略**
   - 关闭脆弱降级逻辑，保留最小可信路径。
   - 优点：安全性更好。
   - 缺点：需要检查历史兼容。
   - 优先级：高
   - 工作量：4-6 人天

2. **画像分级存储**
   - 普通画像、敏感画像、教学画像分开管理。
   - 优点：便于权限隔离。
   - 缺点：模型和接口要分层。
   - 优先级：中
   - 工作量：5-8 人天

3. **文件访问策略细化**
   - 为下载资源、课件和导出文件设置不同权限。
   - 优点：更符合教育场景。
   - 缺点：路径管理要更严谨。
   - 优先级：中
   - 工作量：3-5 人天

推荐：

- 优先修复 JWT 和文件权限，再做画像分级。

### 2.9 可维护性与扩展性

问题：

- 提示词硬编码。
- 缺少 OpenAPI 契约驱动。
- 测试覆盖不足。
- 日志监控不完整。

可行方案：

1. **Prompt 外部化**
   - 提示词按模块拆到独立文件。
   - 优点：方便调优和复用。
   - 缺点：需要建立版本规则。
   - 优先级：高
   - 工作量：4-6 人天

2. **接口契约对齐**
   - 以 OpenAPI / 类型定义为单一事实来源。
   - 优点：前后端不易漂。
   - 缺点：要同步整理现有接口。
   - 优先级：高
   - 工作量：5-8 人天

3. **测试和日志补齐**
   - 为关键路径补单测、集成测试和结构化日志。
   - 优点：后续改动更稳。
   - 缺点：一次性投入偏大。
   - 优先级：高
   - 工作量：6-12 人天

推荐：

- 先外部化 Prompt，再补契约和测试。

### 2.10 其他体验项

问题：

- 前端重复代码。
- 无国际化。
- 缺少用户反馈入口。
- 缺少成本估算。

可行方案：

1. **前端公共工厂与组合式封装**
   - 统一表单、请求、状态和空态组件。
   - 优点：减少重复。
   - 缺点：需要回收散落代码。
   - 优先级：中
   - 工作量：4-7 人天

2. **轻量国际化**
   - 先把中文文案抽成字典。
   - 优点：后续扩语言容易。
   - 缺点：初期收益不高。
   - 优先级：低
   - 工作量：3-5 人天

3. **反馈与成本统计**
   - 记录用户满意度、生成耗时和 token 估算。
   - 优点：能指导优化优先级。
   - 缺点：需要埋点。
   - 优先级：中
   - 工作量：3-6 人天

推荐：

- 先做公共封装和反馈统计，国际化后置。

## 3. 改进路线图

### 第一阶段：稳住主链路

目标：

- 先把“生成、评价、错题、资源、问答”主链路做稳。

建议任务：

- 固化关键字段契约。
- 增加熔断、重试和快照缓存。
- 修复错题本和问答同步的科目归类。
- 清理提示词中的硬编码兜底。

### 第二阶段：提升质量

目标：

- 让生成内容和路径推荐更像“教学系统”，而不是“模板拼接器”。

建议任务：

- 生成计划配置化。
- 报告模板 + LLM 润色。
- 多路径模板。
- 错题按错误模式重练。

### 第三阶段：补齐知识体系

目标：

- 让 RAG、图谱和画像形成可回滚、可审计、可验证的数据闭环。

建议任务：

- RAG 版本控制。
- 统一知识点实体 ID。
- 图谱与 SQL 最终一致性同步。
- 画像置信度校验。

### 第四阶段：面向扩展

目标：

- 让系统可以持续接入新学科、新智能体和新页面。

建议任务：

- 能力注册和拓扑编排。
- 前端工厂化封装。
- OpenAPI 契约与测试补齐。
- 可观测性和成本统计。

## 4. 成本收益判断

### 预期收益

- 生成调用更少：多变体单次生成、模板+润色模式可减少重复 LLM 调用。
- 响应更稳：熔断和快照缓存能降低超时感知。
- 可回滚：RAG 版本化和知识点统一 ID 让内容更新更安全。
- 更易维护：Prompt 外部化和接口契约化能降低后续改动成本。

### 粗略收益估计

以下为经验型估算，不是严格统计：

- 课件/报告类 token 消耗：可下降约 20% - 40%。
- 问答首屏响应：通过缓存和分段加载可下降约 15% - 30%。
- 错题定位时间：通过科目直达和全局视图可下降约 50% 以上。
- 失败重试成本：通过熔断和退避重试可显著减少重复调用。

### 风险

- 过早引入复杂编排会增加维护成本。
- 过度模板化会让内容变僵。
- 数据版本化会增加存储和清理任务。
- 图谱和画像校验规则需要持续调参。

---

## 5. 推荐落地顺序

如果只做一轮，我建议先做这 5 件事：

1. 错题本科目化和问答错题同步。
2. LLM 熔断、重试和快照缓存。
3. 生成计划与学科规则配置化。
4. 报告模板化输出。
5. RAG 版本控制和知识点统一 ID。

如果要做成长期路线，再继续补：

- 能力注册 + 拓扑编排
- SM-2 掌握度
- 最终一致性同步
- 前端公共工厂
- 埋点和成本统计
