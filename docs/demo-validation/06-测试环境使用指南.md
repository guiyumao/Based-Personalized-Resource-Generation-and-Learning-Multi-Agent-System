## 2. 启动项目

全量启动（与 README 一致）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_local_services.ps1
```

只重启教师服务（8005，演示数据的主要提供方）：

```powershell
$repo = 'C:\Users\wdx\Desktop\基于大模型的个性化资源生成与学习多智能体系统'
$env:DATABASE_URL = 'sqlite+pysqlite:///' + (Join-Path $repo 'artifacts\local-start-20261019\runtime.sqlite').Replace('\','/')
Set-Location $repo
C:\Users\wdx\anaconda3\python.exe -m uvicorn services.teacher_service.app.main:app --host 127.0.0.1 --port 8005 --lifespan off
```

健康检查：

```bash
curl --noproxy '*' http://127.0.0.1:8005/health
```

> 本轮为加载缺陷修复重启过 8005。若该进程随终端/会话退出，请用上面的命令重新启动，演示数据不会丢失（数据在 SQLite 文件里）。

## 3. 演示数据的四种操作

```bash
# 1) 只读检查：账号、计数、一致性（不改任何数据）
python scripts/demo_teaching_dataset.py --db artifacts/local-start-20261019/runtime.sqlite --action check

# 2) 初始化（幂等；执行前自动备份）
python scripts/demo_teaching_dataset.py --db artifacts/local-start-20261019/runtime.sqlite --action seed

# 3) 时间对齐（环境放置多日后，把进行中的作业/打卡窗口拉回当前）
python scripts/demo_teaching_dataset.py --db artifacts/local-start-20261019/runtime.sqlite --action refresh

# 4) 清理（仅删除 demo_% 账号及其业务数据，需 --yes）
python scripts/demo_teaching_dataset.py --db artifacts/local-start-20261019/runtime.sqlite --action reset --yes

# 5) 演示题库准备（只造题、补教学范围，不写任何作答）
#    seed 已自动调用；单独运行用于重建题库
python scripts/demo_learning_evidence.py --db artifacts/local-start-20261019/runtime.sqlite --per-point 20

# 5b) 回到「零学情」：删掉演示题库及其全部作答，可重新跑角色用例观察学情从 0 长出来
python scripts/demo_learning_evidence.py --db artifacts/local-start-20261019/runtime.sqlite --reset

# 6) 角色真实联动用例：管理员 / 教师 / 学生三方走完整业务，学情由学生真实作答产生
python scripts/demo_role_use_cases.py --db artifacts/local-start-20261019/runtime.sqlite

# 6b) 只清理上一次用例留下的 [USECASE] 临时数据（作答保留）
python scripts/demo_role_use_cases.py --db artifacts/local-start-20261019/runtime.sqlite --cleanup-only

# 7) 学习画像（模型生成）角色用例：学生自述 -> DeepSeek 真实生成画像 -> 缓存/人工覆盖/越权/边界
#    轴值全部由模型产出，脚本不提供任何数值；详见 08-学习画像模型生成验证.md
python scripts/demo_portrait_use_cases.py               # 全量 24 名学生（已生成的走缓存，不重复调模型）
python scripts/demo_portrait_use_cases.py --verify-only # 只校验已持久化画像，零模型调用
```

> **学情为什么分两步**：`seed` 只准备"能被证据层接纳的客观题"，一行答案都不写。
> 学情必须由学生在跑起来（8001 / 8004 / 8005 / 8006 都要在线）通过
> `POST /evaluation/batch_submit` 真实作答产生——`is_correct` 由
> `ReportService._compare_objective_answer` 比对得出，`ProfileUpdater` 再递推掌握度。
> 所以只跑 `seed` 就去看教师端学情，一定是空的，这是设计如此，不是故障。

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--json` | 输出机器可读结果（便于存档与比对） |
| `--refresh` | `seed` 时顺带对齐时间窗口 |
| `--yes` | `reset` 必须显式确认 |

备份位置：`artifacts/demo-teaching/backups/before-demo-seed-<时间戳>.sqlite`。

## 4. 自动化验证

### 4.1 跨角色端到端回归

```bash
python scripts/verify_demo_teaching.py --db artifacts/local-start-20261019/runtime.sqlite
```

- 需要 8001 与 8005 正在运行。
- 脚本会创建 `[VERIFY]` 前缀的临时班级/作业/考勤，结束后自动清理。
- 结果写入 `artifacts/demo-teaching/verify-<时间戳>/result.json`，控制台最后一行给出通过数与证据路径。
- 退出码：`0` 全部通过，`1` 存在失败。

### 4.2 角色用例（含联动，学情由它产出）

```bash
python scripts/demo_role_use_cases.py --db artifacts/local-start-20261019/runtime.sqlite
```

- 需要 **8001 / 8004 / 8005 / 8006** 同时在线（评估服务负责判分，系统服务是管理员端）。
- 会为每个有题库的演示教学班完整跑一遍：教师准备 → 学生执行 → 教师批改 → 学情前后对比，
  另含管理员治理与越权/边界用例；临时数据前缀 `[USECASE]`，结束后自动清理，**作答保留**。
- 耗时约 20 分钟（学生作答逐题走 HTTP，34 人次 × 10 题）。
- 产物：`artifacts/demo-teaching/role-usecases-<时间戳>/result.json` 与 `report.md`。
- 常用参数：

| 参数 | 说明 |
| --- | --- |
| `--per-student N` | 每人作答题数，默认 10（< 8 达不到证据层 sufficient 阈值，洞察会缺值） |
| `--keep` | 不清理 `[USECASE]` 临时数据，便于人工复查页面 |
| `--cleanup-only` | 只做清理，不跑用例 |

只跑缺陷回归单测：

```bash
python -m pytest tests/unit/test_teacher_scope_paths.py -q
```

## 5. 数据完整性核验口径

`--action check` 会校验 7 类规则，输出 `issues: []` 才算健康：

1. 每个教学班的 `teacher_user_id` 都是有效教师；
2. 所有选课记录指向有效、启用的学生；
3. 不存在"非本班学生"的作业提交；
4. 作业的教师归属与其班级一致；
5. 打卡提交者必须是该班级成员；
6. 演示数据不得把通知投递给非演示账号；
7. 班级名称不得重复。

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'sqlalchemy'` | 用了托管 Python | 改用 `C:\Users\wdx\anaconda3\python.exe` |
| `database not found` | `--db` 路径错 | 用 `artifacts/local-start-20261019/runtime.sqlite` 的绝对路径 |
| `refusing to write demo data into learning_system.db` | 安全保护 | 换运行库，或确认目标后手动指定其他路径 |
| `curl` 返回 502 但服务在跑 | 本机设置了 HTTP 代理 | 加 `--noproxy '*'` |
| 8005 连接被拒 | 进程未启动/已退出 | 用第 2 节命令重启，`/health` 返回 200 即可 |
| 作业/打卡全部"已截止" | 环境放置多日 | `--action refresh` |
| 教师看不到班级 | 8005 连的是旧库 | 检查启动时的 `DATABASE_URL` 是否指向 `runtime.sqlite` |
| 学生提示"已加入"但人数不变 | 唯一约束生效，属幂等 | 正常行为，不需要处理 |
| 教师端学情全 0（掌握度"暂无数据"） | 只跑了 `seed`，没有跑角色用例或执行过 `--reset` | 跑 `demo_role_use_cases.py`（或先 `demo_learning_evidence.py --per-point 20` 再跑） |
| 学情有值但某个班为 0 | 该课程在系统学科目录里没有已发布题目（数据库原理 / Java / Python / 软件工程） | 真实情况，见 `demo_learning_evidence.py` 输出的 `skipped` 列表，不要伪造题目 |
| 角色用例报 "Non-member" / 403 类失败 | 跨班选修关系与预期不同 | 先确认 `class_enrollments` 实际成员，再调整剧本学生选择；不要把 403 改成 200 |
| 作答没有新增记录 | 同名 `client_request_id` 幂等退回 | 正常行为；要重新计分先 `demo_learning_evidence.py --reset` |

## 7. 安全边界

- `seed` / `reset` 只操作 `demo_` 前缀账号及其派生数据；真实账号、真实班级、公共知识库不受影响。
- `reset` 前自动备份；如需回滚，直接复制备份文件覆盖运行库（先停 8005）。
- 本文所有命令均已在本机实际执行过；未验证的命令不会写在此处。
- 未开启 `RUN_LIVE_LLM`，因此不会产生模型调用费用。
