## 1. 这个功能为什么是"模型生成"而不是人工

`services/user_service/app/services/learning_style_inference.py`：

- 前端雷达图的四个轴（信息加工/信息感知/信息输入/理解方式）来自 `POST /users/{id}/learning-portrait/infer`：服务端把该生已收集的证据（本人自述 `profile_dimensions`、已判分作答、资源浏览、画像对话）组装成上下文，调用聊天模型，模型返回每轴 `value/confidence/evidence`，持久化到 `UserProfile.habits["learning_style_inference"]`。
- 人工入口（`PUT .../learning-portrait`）只负责两件真实的产品行为：学生填写**自述维度**（模型的输入之一），或**手动覆盖某个轴**（`source=user_reported`，模型永不覆盖）。
- 证据不足的轴模型返回 `null`，页面如实显示"尚未获得"——不为填满雷达而编造（本仓库提示词规则 3）。
- 指纹缓存：自述/作答等证据不变时，24 小时内重复触发直接返回 `cached=True`，不重复消耗模型。

| 学习困难（自述"需要步骤演示/反复练"） | 信息感知≈+0.6（感知）、理解方式≈+0.7（序列，置信度更高） | s06 / s07 / s14 / s22 / s23 |
| 待观察 | 信息感知≈+0.4~0.5、理解方式≈+0.5~0.6（幅度更小、置信度更低） | s08 / s16 / s24 |

值得注意的三点（恰好证明不是硬编码）：

1. **方向随自述翻转**：自述写"先搭框架"的学生得到负值（直觉/全局），写"先看例子"的得到正值（感知/序列）——同一接口、不同输入、相反结论。
2. **同画像学生数值也不相同**：s02 感知 0.5/序列 0.4，s04 感知 0.6/序列 0.5——模型输出带真实波动。
3. **"信息输入"轴全员 missing**：这批学生没有任何资源浏览记录（`resources=0`），模型对视觉/言语偏好无证据，一律留空并在 summary 里说明"输入维度证据不足"。

## 4. 与前序角色用例的联动关系

- 画像生成消费的作答证据，正是 `demo_role_use_cases.py` 里学生通过 `POST /evaluation/batch_submit` 真实作答产生的（`answers ≥ 10`）。
- 因此完整链路为：教师建班/发范围 → 学生作答（服务端判分）→ 学生自述 → **模型生成画像** → 管理员可审计查看；任一环节删除证据，画像相应轴即回落为 missing/stale。

## 5. 复现命令

```bash
# 全量（约 1 分钟；已生成的学生在缓存期内走 cached，不重复消耗模型）
python scripts/demo_portrait_use_cases.py

# 只校验已持久化状态，零模型调用
python scripts/demo_portrait_use_cases.py --verify-only

# 少量学生冒烟
python scripts/demo_portrait_use_cases.py --students 3
```

> 注意：`demo_teaching_dataset.py --action reset` 会连同 `UserProfile` 一起清理（含自述与已生成画像），重建后需重新执行本脚本恢复画像数据。
