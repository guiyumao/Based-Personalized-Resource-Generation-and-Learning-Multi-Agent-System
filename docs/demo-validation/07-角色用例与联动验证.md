## 1. 为什么要有这份文档

之前的演示数据是**脚本按画像把答案直接写进数据库**：覆盖率写 0.92/0.72/0.38/0.55，
掌握度是被"分配"出来的 90 / 70 / 40 / 60。那不是系统算出来的，是把期望值写进了结果。

现在改成：

```
准备阶段（脚本）              角色阶段（全部走 HTTP，真实账号）
─────────────────────        ─────────────────────────────────────────
只造「公共演示客观题」    →    学生登录 → 逐题作答 POST /evaluation/batch_submit
只补「教学范围」          →    服务端比对标准答案判 is_correct
                         →    ProfileUpdater 递推掌握度
                         →    教师端洞察 / 教学分析 读出数值
```

区别就在中间那一步：`is_correct` 不再由我们决定，而是 `ReportService._compare_objective_answer`
拿学生提交的内容和题库里存的标准答案比对得出来的。报告里的每个掌握度、错题数、正确率，
都能追溯到某一次具体的 HTTP 作答请求。

## 5. 学情是怎么跑出来的

### 5.1 链路

1. `scripts/demo_learning_evidence.py` 只做两件事：复制公共客观题成**演示题库**（去掉
   `generated_for_user_id`，否则证据层会排除其他学生的作答）、把有题知识点补进 `TeachingScope`。
   **它不写任何 `answer_records`。**
2. 学生登录后 `POST /evaluation/batch_submit`，提交的是他自己"选的答案"：答对就用标准答案，
   答错就真的选另一个干扰项 / 判断题取反 / 填空写"不确定（未掌握该知识点）"。
3. 服务端比对 → `is_correct` → `ProfileUpdater` 递推 → `load_evidence` 汇总 → 教师端接口读出。

## 8. 复现方式

```bash
# 1) 准备题库与账号（不写作答）
python scripts/demo_teaching_dataset.py --db artifacts/local-start-20261019/runtime.sqlite --action seed
python scripts/demo_learning_evidence.py --db artifacts/local-start-20261019/runtime.sqlite --per-point 20

# 2) 角色真实联动（约 20 分钟，结束后自动清理 [USECASE] 临时数据，作答保留）
python scripts/demo_role_use_cases.py --db artifacts/local-start-20261019/runtime.sqlite

# 3) 只清理遗留的临时数据
python scripts/demo_role_use_cases.py --db artifacts/local-start-20261019/runtime.sqlite --cleanup-only

# 4) 想回到"零学情"重新跑
python scripts/demo_learning_evidence.py --db artifacts/local-start-20261019/runtime.sqlite --reset
```

作答用 `client_request_id=uc-<学生>-<题号>` 做幂等键，重复执行同一批题不会产生重复记录，
因此这套用例可以反复重放；`--per-student N` 可调整每人题量（≥8 才能满足证据层的 sufficient 阈值）。
