## 二、实现内容

班级归属仍由登录身份决定，教师显示姓名不参与权限判断。教师可创建、修改、启停自己的班级，复制或重新生成邀请码，查看成员和人数、作业数并移出成员。邀请码重新生成后旧码失效；停用班级不能入班、发布新作业或接收新提交。重复加入返回同一关联，数据库唯一约束兜底。

学生从原“班级空间”进入“我的班级”，输入邀请码、核对班级和教师后确认加入。作业和讨论的班级选项来自真实成员关系。作业发布、提交、批改均写入原业务表；教师选择提交即可评分；学生只能收到自己提交的内容、成绩和历史。截止时间输入携带时区并转为 UTC 比较；过期、停用作业显示明确状态。

沿用右上角悬浮通知入口和既有消息系统：学生入班通知所属教师，发布作业通知成员，学生提交通知作业教师，批改通知原提交学生。已读状态和未读数来自原持久通知表。

主要文件：

- `common/models/learning.py`：Classroom 增加 invite_code/status，新增 SubmissionRevision。
- `alembic/versions/20261022_0035_classroom_loop.py`：接续 0034 的增量迁移，补历史邀请码、唯一索引与提交历史表。
- `services/teacher_service/app/services/classroom_membership.py`：成员、邀请码、班级信息与状态管理。
- `services/teacher_service/app/services/teacher_manager.py`：原作业、提交、批改、分析与范围逻辑修复；SQLite 短写事务在读取前加锁，其他数据库使用行锁及唯一约束。
- `services/teacher_service/app/api/routes/classes.py`、`schemas/teacher.py`：新成员接口和兼容性的响应扩展、身份及参数校验。
- `web-app/src/components/TeacherClassPanel.vue`、`views/TeacherView.vue`：真实班级详情、成员管理和无需输入记录 ID 的批改流程。
- `web-app/src/views/student/ClassroomView.vue`、`api/types.ts`：“我的班级”、入班、范围课件、本人提交和批改结果。
- `tests/unit/test_classroom_loop.py`、`test_teacher_insights.py`：业务、权限、并发、证据隔离及事务回滚验证。旧学情测试从“假定班级 1 代表全部学生”改为真实班级与成员 fixture，不再要求拉取跨课程私人报告。

新增接口均在现有 `/teacher` 下：`GET /students/me/classes`，`POST /students/me/classes/lookup`、`/join`，`GET /classes/{id}/members`，`PATCH /classes/{id}`，`POST /classes/{id}/invite`，`DELETE /classes/{id}/members/{student_id}`。原作业、提交、批改和通知接口继续使用。

## 五、验收边界与使用方式

本轮确认完整师生业务链在同一真实隔离后端/数据库中持续运行；当前用户运行环境完成安全迁移、服务激活和只读复核。没有在 `teacher111` 的真实班级中创建验收作业或修改其学生成绩。

学生无需等待后台审批：邀请码校验通过后直接建立成员关系。修改未评分答案保留旧版本；评分后锁定学生覆盖，教师仍可通过原批改流程更正分数并保留历史。原系统没有草稿或班级审批业务，本次没有新建不完整的草稿/审批状态。

练习历史没有原生 class_id，统计关联依据为“当前成员 + 班级学科目录 + 教师范围内的权威知识点 + 有效学习证据”，不能据此声称已恢复每道历史练习的原始发起班级；无法明确匹配学科/知识点时不纳入。作业及成绩则具备明确的班级外键。教师详情现在展示本班证据报告，学生自己的全局报告入口保留。公共知识自动建设、检索、审核、智能生成的真实付费效果不属于本次无费用验收，不宣称已验证。

双端按重新读取接口同步，提供明确刷新按钮；通知继续按已有轮询/在线恢复机制更新，本次未新增 WebSocket。PostgreSQL/MySQL 的真实运行验收未执行，当前持久化及并发证据基于 SQLite。

现在刷新当前页面：教师从“班级管理”创建班级并复制邀请码；学生在“班级空间 → 我的班级”查找并确认加入；教师到“作业管理”选班发布作业，再点作业和学生提交进行批改。学生在同一班级空间查看成绩、评语及历史。
