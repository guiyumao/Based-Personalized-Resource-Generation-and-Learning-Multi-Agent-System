## 传输层功能与端口

- 提供应用进程之间的逻辑通信（网络层是主机之间）；复用与分用；端到端差错检测。
- 端口 16 位：熟知端口 FTP 21、SSH 22、Telnet 23、SMTP 25、DNS 53、HTTP 80、HTTPS 443、POP3 110、SNMP 161；套接字 = (IP:端口)。

## UDP

面向报文、无连接、尽力交付、支持一对多、首部 8B：源端口、目的端口、长度、校验和（可选）。校验和计算含伪首部（IP 地址信息）且需补偶数字节（补 0）， UDP 校验错则丢弃或交应用层处理。适用于实时应用（RTP、DNS、DHCP）。

## TCP 段与序号

首部 20~60B：源/目的端口、序号 seq（字节流编号）、确认号 ack（期望收到的下一字节）、数据偏移、标志位（ACK、SYN、FIN、RST、PSH、URG）、窗口（接收窗口）、校验和、紧急指针。MSS 之外的选项字段。TCP 面向字节流、全双工、点对点、可靠有序。

## 连接管理

- 三次握手：SYN=1,seq=x → SYN=1,ACK=1,seq=y,ack=x+1 → ACK=1,seq=x+1,ack=y+1（第三次可携数据）。三次而非两次的原因：防止已失效的连接请求报文突然到达造成资源浪费，并同步双方初始序号。
- 四次挥手：FIN=1,seq=u → ACK=1,ack=u+1（可合并）→ FIN=1,ACK=1,seq=w,ack=u+1 → ACK=1,ack=w+1。主动方进入 TIME-WAIT 等 2MSL：保证最后的 ACK 能重传、让本连接的旧报文在网络中消逝。
- SYN 洪泛攻击与 SYN Cookie、半连接队列。

## 可靠传输

序号 + 确认（累积确认）+ 重传。超时重传的 RTO 由 RTT 加权平均自适应计算（RTTs = (1-α)×RTTs + α×RTT 样本，α 通常 1/8）。快速重传：收到 3 个重复 ACK 立即重传，不必等超时。SACK 选择确认可告知不连续收到区间。

## 流量控制

滑动窗口机制：接收方通过 rwnd 通告可用缓存；发送窗口 = min(rwnd, cwnd)。零窗口时发送方启动持续计时器，到时发零窗口探测报文防死锁。

## 拥塞控制

发送方维护 cwnd，实际发送窗口 = min(rwnd, cwnd)：

1. 慢开始：cwnd 从 1 MSS 起，每收到一个 ACK 拥塞窗口 +1，每轮 RTT 翻倍，直到慢开始门限 ssthresh。
2. 拥塞避免：cwnd ≥ ssthresh 后每 RTT 加 1 MSS（线性增长）。
3. 超时（判断网络拥塞）：ssthresh = 当前 cwnd/2，cwnd 重置 1，重新慢开始。
4. 快重传 + 快恢复（收到 3 个重复 ACK）：立即重传丢失段；ssthresh = cwnd/2，cwnd = 新 ssthresh（快恢复）进入拥塞避免。

经典计算题：画出逐 RTT 的 cwnd 变化，标出慢开始/拥塞避免/超时/快恢复各阶段。

## 高频考查方式与易错点

1. 握手挥手各报文的 seq/ack/标志位数值——按字节序号规则逐个推。
2. TIME-WAIT 2MSL 的原因（两点缺一不可）。
3. 拥塞窗口计算题注意"收到 3 个重复 ACK"走快恢复而非重新慢开始。
4. 确认号是期望的下一个字节序号，不是已收到的最后一个。
