# 队列与栈

## 一、定义与适用条件

**栈（Stack）** 是只允许在一端（称为栈顶 top）进行插入和删除的线性表，其插入称为入栈（push），删除称为出栈（pop）。栈遵循后进先出（LIFO，Last In First Out）原则。

**队列（Queue）** 是只允许在一端（队尾 rear）插入、在另一端（队头 front）删除的线性表，插入称为入队（enqueue），删除称为出队（dequeue）。队列遵循先进先出（FIFO，First In First Out）原则。

两者的共同前提是：元素之间存在线性次序，且所有操作只发生在端点。适用条件如下：

1. 栈适用于需要“最近优先”回退或嵌套匹配的场景，如函数调用栈、括号匹配、表达式求值、深度优先搜索的显式栈、撤销操作。
2. 队列适用于需要“先来先服务”的场景，如广度优先搜索、任务调度、缓冲区、打印队列。
3. 若需要两端都能插入删除，应使用双端队列（deque），不能强行用普通栈或队列模拟，否则操作语义会失真。

## 二、原理与推导

### 2.1 栈的顺序存储原理

用数组 `data[0..capacity-1]` 存储，维护整数 `top` 表示栈顶元素下标。约定空栈时 `top = -1`。则：

- 栈中元素个数为 `top + 1`；
- 入栈：先判断 `top == capacity - 1` 是否成立（栈满），不成立则 `top = top + 1`，再令 `data[top] = x`；
- 出栈：先判断 `top == -1` 是否成立（栈空），不成立则取出 `data[top]`，再令 `top = top - 1`。

不变量：任意时刻，`-1 ≤ top ≤ capacity - 1`，且 `data[0..top]` 恰好是当前栈内元素，按从栈底到栈顶排列。

### 2.2 队列的循环顺序存储原理

普通顺序队列出队后队头前移，会造成“假溢出”：数组前端有空位但队尾已到末尾。解决办法是把数组视为环，下标对 `capacity` 取模。

维护 `front`（队头元素下标）与 `rear`（下一个可插入位置的下标），元素个数为 `(rear - front + capacity) % capacity`。为区分“队空”和“队满”，常用两种方案：

- **方案 A（牺牲一个单元）**：队空条件 `front == rear`；队满条件 `(rear + 1) % capacity == front`。此时最多存 `capacity - 1` 个元素。
- **方案 B（计数变量）**：额外维护 `size`，队空 `size == 0`，队满 `size == capacity`，可存满 `capacity` 个元素。

入队：若队满则失败；否则 `data[rear] = x`，`rear = (rear + 1) % capacity`。
出队：若队空则失败；否则取出 `data[front]`，`front = (front + 1) % capacity`。

不变量（方案 A）：`0 ≤ front, rear < capacity`，且队列中元素按 `front, front+1, …, rear-1`（模 capacity）的顺序排列，元素个数为 `(rear - front + capacity) % capacity`，且该值恒小于 `capacity`。

### 2.3 链式存储原理

栈和队列都可用单链表实现。栈用头插头删，入栈出栈均为 O(1)。队列需同时维护头指针和尾指针：入队在尾指针后插入并更新尾指针，出队删除头结点并更新头指针；出队后若队列变空，必须把尾指针重新置为与头指针一致（或置空），否则尾指针悬空，后续入队会出错。这是链式队列最容易遗漏的不变量维护点。

### 2.4 复杂度前提

顺序栈与循环队列的入栈、出栈、入队、出队均为 O(1)，前提是容量已预分配且不触发扩容。若采用动态扩容（如容量不足时申请两倍空间并复制），单次操作最坏 O(n)，但 n 次连续操作均摊 O(1)。链式实现各操作 O(1)，前提是已持有相应端点指针；链式队列若只有头指针，入队需遍历到尾部，退化为 O(n)。

## 三、完整步骤

### 3.1 顺序栈操作步骤

1. 初始化：`capacity` 给定，`top = -1`。
2. 入栈 x：检查 `top == capacity - 1`，是则报“栈满”；否则 `top++`，`data[top] = x`。
3. 出栈：检查 `top == -1`，是则报“栈空”；否则取 `y = data[top]`，`top--`，返回 y。
4. 取栈顶：检查栈空，非空返回 `data[top]`，不修改 `top`。

### 3.2 循环队列操作步骤（方案 A）

1. 初始化：`front = 0`，`rear = 0`。
2. 入队 x：若 `(rear + 1) % capacity == front`，报“队满”；否则 `data[rear] = x`，`rear = (rear + 1) % capacity`。
3. 出队：若 `front == rear`，报“队空”；否则取 `y = data[front]`，`front = (front + 1) % capacity`，返回 y。
4. 求长度：`(rear - front + capacity) % capacity`。

### 3.3 链式队列出队后的指针维护步骤

1. 若 `front == null`，报“队空”。
2. 令 `p = front`，`front = front.next`。
3. 若 `front == null`（队列已空），令 `rear = null`。
4. 释放 p，返回其数据。

## 四、可验算案例

**案例 1：顺序栈。** 取 `capacity = 4`，初始 `top = -1`。依次入栈 5、8、3，再出栈一次，再入栈 7。

| 操作 | 操作前 top | 判断 | 操作后 top | 栈内容（底→顶） |
|---|---|---|---|---|
| 入栈 5 | -1 | 未满 | 0 | 5 |
| 入栈 8 | 0 | 未满 | 1 | 5, 8 |
| 入栈 3 | 1 | 未满 | 2 | 5, 8, 3 |
| 出栈 | 2 | 非空 | 1 | 5, 8（返回 3） |
| 入栈 7 | 1 | 未满 | 2 | 5, 8, 7 |

验算：最终元素个数 `top + 1 = 3`，与表中 3 个元素一致；出栈返回值 3 与出栈前栈顶一致。

**案例 2：循环队列（方案 A）。** 取 `capacity = 4`，最多存 3 个元素。初始 `front = 0, rear = 0`。依次入队 A、B、C，出队一次，再入队 D。

| 操作 | 操作前 (front, rear) | 判断 | 操作后 (front, rear) | 队列内容（头→尾） |
|---|---|---|---|---|
| 入队 A | (0,0) | 未满 | (0,1) | A |
| 入队 B | (0,1) | 未满 | (0,2) | A, B |
| 入队 C | (0,2) | 未满 | (0,3) | A, B, C |
| 出队 | (0,3) | 非空 | (1,3) | B, C（返回 A） |
| 入队 D | (1,3) | `(3+1)%4=0 ≠ 1`，未满 | (1,0) | B, C, D |

验算：最后 `(front, rear) = (1, 0)`，长度 `(0 - 1 + 4) % 4 = 3`，与队列中 B、C、D 三个元素一致；`rear` 已回绕到下标 0，说明循环生效。此时若再入队，判断 `(0+1)%4 = 1 == front`，正确报告队满。

## 五、边界与反例

1. **空结构操作**：对空栈出栈、对空队列出队都必须先判空，否则顺序栈会读到 `data[-1]`，循环队列会读到无效位置。
2. **满结构操作**：顺序栈满时入栈、方案 A 循环队列满时入队都必须拒绝，不能覆盖已有元素。
3. **循环队列的“满”误判**：方案 A 中 `capacity = 1` 时永远队满，因为 `(0+1)%1 = 0 == front`。若确实需要存 1 个元素，应改用方案 B 或增大容量。
4. **链式队列尾指针悬空反例**：队列中只有元素 X，出队后若只更新 `front = null` 而不更新 `rear`，`rear` 仍指向已释放结点；下次入队会在已释放结点后链接，造成错误。正确做法是出队后队列为空时同步置 `rear = null`。
5. **栈与队列不可互换的反例**：入队序列 1、2、3，队列出队顺序必为 1、2、3；若用栈存储则出队顺序为 3、2、1。用栈模拟队列需要两个栈并配合“倒栈”规则，不能直接套用。
6. **下标取模的负数问题**：某些语言中负数取模结果为负，计算长度时须写成 `(rear - front + capacity) % capacity`，不能省略 `+ capacity`。

## 六、常见错误

1. 顺序栈入栈时先赋值后自增，导致覆盖 `data[top]` 原值；正确顺序是先 `top++` 再赋值。
2. 循环队列用 `rear == front` 同时表示空和满，未加区分手段，导致无法判断状态。
3. 出队只移动 `front` 而不取模，数组用完后无法回绕。
4. 链式栈误用尾插尾删，导致出栈需遍历，复杂度退化为 O(n)。
5. 把“栈顶指针指向栈顶元素”和“指向栈顶上一空位”两种约定混用，造成判空条件写错。本文统一采用前者（空栈 `top = -1`），换约定时必须整体改写判空、判满与计数公式。
6. 忽略均摊分析前提，把动态扩容栈的单次最坏 O(n) 误说成每次 O(1)。

## 七、总结

栈与队列都是操作受限的线性表，核心区别在操作端点数与出队次序：栈单端操作、后进先出；队列双端分工、先进先出。实现要点是维护好各自的不变量：顺序栈的 `top` 范围、循环队列的取模下标与空满判别、链式队列出队为空时的尾指针复位。分析复杂度时必须说明容量是否预分配、是否触发扩容、是否持有端点指针这些前提。判断实现是否正确，可用“操作前后不变量是否保持”和“小规模手工验算能否代回”两条标准检验。
